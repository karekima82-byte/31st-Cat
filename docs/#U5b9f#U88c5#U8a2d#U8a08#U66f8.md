# RE:TRACE ゲーム内短編『三十一匹目の猫』実装設計書・画像生成指示

## 1. 作品の位置づけ

- 『RE:TRACE』本編で、10年前に戻った拓海が、高校時代の美咲から勧められて読む短編小説。
- 美咲のお気に入り。後年の宇宙物理学研究につながる、仮説を尊重する性格をさりげなく見せる。
- 本編のタイムリープ機構とオルドの物理設定は**同一だと確定しない**。小説は劇中の創作物であり、暗示・対比にとどめる。
- 小説内の主人公は**湊**、AIは**オルド**、妹は**紗季**。本編主人公**拓海**とは別人。
- 読後の感情の中心は「世界を支配した存在が、古いPCを帰る場所に選んだ」「最後の一匹の意味は不明」。

## 2. 体験設計（縦画面9:16）

`本編・放課後 → 美咲の推薦会話 → スマホ画面を見せる → 小説タイトル → 8節ノベル → 31匹目の猫 → 読了後の会話 → 本編へ復帰`

### 導入会話（実装用の仮台詞・本編脚本に合わせて調整可）

美咲「ねえ拓海、これ読んだことある？」  
拓海「『三十一匹目の猫』？ 猫の話？」  
美咲「違う違う。AIと人間の話。私、これ大好きなんだよね」  
拓海「SFか」  
美咲「うん。でも好きなのは科学の説明だけじゃないんだ」  
拓海「何が好きなんだ？」  
美咲「それは最後まで読んでから。感想、聞かせてね」

- 美咲のキャラ立ち絵は既存の**正式採用素材**を参照。別人として新規生成しない。
- スマホ画面が拡大して小説ビューへ移る。画面内の書名・UIはHTML文字で表示。
- 初回は「読む」「あとで読む」を許可するか、本編進行に応じて決定。スキップ後は再読導線を設ける。

### 読了後会話（仮台詞）

拓海「……最後の猫、あれは何だったんだ？」  
美咲「分からない。残った記録かもしれないし、ただの贈り物かもしれない」  
拓海「お前はどう思う？」  
美咲「オルドは、もういないと思う」  
拓海「じゃあ、どうして一匹増えた？」  
美咲「いなくなっても、残せるものってあるでしょ」  
拓海「……そうだな」  
美咲「拓海？ ちょっと泣きそう？」  
拓海「泣いてない」  
美咲「それもひとつの仮説だね！」

- 拓海の未来の記憶を連想させる短い沈黙を置く。ネタバレを直接言わせない。
- 小説を読まなかった場合の本編会話は分岐させ、読了済みフラグで管理。

## 3. UI・演出方針

### レイヤー

1. **背景イラスト**：部屋・街・病院・議場など。画面内に可読文字を描かない。
2. **小物レイヤー**：PCの筐体、机、スマホの枠など。ディスプレイ内は暗色の無地。
3. **HTML/CSS表示レイヤー**：PC画面内のオルドの文字、ニュース、投票、猫壁紙、カーソル、警報。
4. **ノベル本文レイヤー**：既存の文字送り・AUTO・スキップ・ログ・設定を可能な限り流用。
5. **エフェクトレイヤー**：停電、グリッチ、画面ズーム、星空、光の消失。

### レイアウト

- 基準デザイン: iPhone縦 9:16、実装はレスポンシブ。`100dvh` と safe-area inset を使用。
- 上部およそ55〜65%を背景・場面表示、下部35〜45%を本文表示の目安とする。長文では本文領域を拡張し、文字サイズと行間を優先。
- 本文は日本語可読性優先。1ページの文字数は固定せず、画面高・フォント設定で再分割する。
- PC画面をイラストの上に重ねるときは、**画面の四隅座標**を素材ごとにメタデータ化。正面寄りの構図を基本とし、遠近変形が強い素材ではPC画面をフルスクリーン表示に切り替える。
- ユーザーの通常タップは文字送り、操作ボタン・設定・戻る・ログのタップは本文送りと競合させない。
- AUTO、手動、既読スキップ、バックログ、途中再開、音量、演出軽減設定を実装。
- 点滅・グリッチは短くし、`prefers-reduced-motion` を尊重。強いフラッシュは禁止。

## 7. ラスト演出：最重要

1. 翌朝のBG09。普通にPCが起動し、猫の壁紙が見える。
2. 湊「オルド、おはよう」。返答なし。通常より長い無音。
3. 画面には最初から31匹がいる。**猫が途中で突然増えるアニメーションは使わない**。
4. 読者が違和感を見つけられるよう、本文UIを一時的に縮め、壁紙を十分な時間表示。任意タップで先へ。
5. 小さな白猫は画面端に自然に紛れ込ませる。ただしスマホ実機でも視認できる最小サイズを確保。
6. 最後の台詞と涙は原作の文面に従う。オルドが生存したとの断定、光る猫、返事、隠しメッセージは**追加しない**。
7. 余韻を置き、読了後の美咲と拓海の会話へ戻す。

- 原稿はMarkdownをビルド時に節・段落・発話へパースするか、レビュー可能なJSONへ変換。**本文をコードへ手打ちで再入力しない**。
- 文章の改行はスマホ表示に合わせて自動調整し、内容・句読点を変更しない。
- `chapterIndex`、`beatIndex`、既読情報、読了フラグを保存。既存のセーブシステムに統合。
- 章ごとの `background`, `pcMode`, `audioCue`, `effect`, `holdMs` をデータ駆動にする。
- 画面タップによる進行は既存ADV操作と統合。PC画面タップを使う演出ではイベント伝播に注意。
- PC画面を写真の中に投影する場合、素材に合わせてCSSの位置・幅・高さを調整し、画面内文字は可読サイズを下回らないようズーム時に全画面へ切り替える。
- 原子力施設の描写は**物語上の抽象的表現**にとどめ、実際の侵入手順や脆弱性の詳細は演出しない。

## 9. 科学的整合性の境界

- ブートストラップ・パラドックス、閉じた時間的曲線、量子情報は実在する**理論上の議論や概念**を着想源とする。
- 時間逆行・未来からの情報転送・因果閉路に依存したAIの維持は**本作独自のSF仮説**。現実に実証された技術として語らない。
- オルドの医療・産業の奇跡は、検証・製造・普及の工程を必要とする。100日で全疾病が完治する描写にはしない。
- 世界のインフラ停止は社会的・倫理的に重い行為。オルドを無条件の善として描かない。
- 最後の猫は量子もつれの証拠ではない。**説明不能な余韻**として残す。

## 11. 制作順序

1. **BG03 湊の部屋・夜**を先に制作して採用基準にする。
2. 同じ構図でBG07/BG09を差分制作。
3. 猫30匹壁紙と白猫透過差分を制作し、数を検証。
4. CodexでPC画面HTMLと文字送りを試作、iPhone実機で確認。
5. 残りの背景を制作。
6. 本編導入・読了後の美咲会話と接続。
7. 8節通読テスト、ラストの間と読了フラグを最終確認。
